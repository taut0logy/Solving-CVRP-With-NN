## Project Overview

### What is CVRP?

The Capacitated Vehicle Routing Problem (CVRP) is a classic optimization problem where:

- A fleet of vehicles with limited capacity must deliver goods to customers
- All vehicles start and end at a central depot
- Each customer has a specific demand that must be satisfied
- The goal is to minimize total travel distance while respecting capacity constraints

### Project Goal

This project implements a neural network solution for CVRP using a transformer-based encoder-decoder architecture, adapted from the Vehicle Routing Problem with Backhauls (VRPB) model. The network learns to make routing decisions through supervised learning on solutions generated by traditional algorithms.

### Key Features

- **Transformer Architecture**: Uses attention mechanisms for spatial reasoning
- **Supervised Learning**: Trains on optimal solutions from traditional solvers
- **CUDA Support**: GPU acceleration for training and inference
- **Benchmark Integration**: Tests on standard VRPLIB instances
- **Checkpoint System**: Saves model state after each training epoch
- **Comprehensive Evaluation**: Detailed performance analysis and route visualization

## Model Architecture

### Overall Structure

The CVRP neural network consists of three main components:

```plaintext
Input (Coordinates + Demands) 
    ↓
Encoder (Transformer Layers)
    ↓
Decoder (Attention-based Decision Making)
    ↓
Output (Next Customer Selection)
```

### 1. Input Representation

**Depot Representation**: `[x, y]` coordinates normalized to [0,1] range

**Customer Representation**: `[x, y, demand]` where demand is normalized by vehicle capacity

### 2. Encoder Architecture

- **Type**: Multi-layer transformer encoder
- **Default Layers**: 3 encoder layers
- **Embedding Dimension**: 128
- **Attention Heads**: 8 heads
- **Head Dimension**: 16 (qkv_dim)
- **Feed-Forward Hidden**: 512 dimensions

**Encoder Process**:

1. Linear embedding of input features (coordinates + demands)
2. Multi-head self-attention across all nodes (depot + customers)
3. Feed-forward networks with residual connections
4. Layer normalization for stable training

### 3. Decoder Architecture

- **Type**: Attention-based pointer network
- **Input**: Current node embedding + remaining capacity
- **Output**: Probability distribution over next possible customers

**Decoder Process**:

1. Concatenate current node embedding with capacity information
2. Generate query vector for attention mechanism
3. Compute attention scores over all nodes
4. Apply masking for visited nodes and capacity constraints
5. Output probability distribution for next customer selection

## Training Process

### Phase 1: Data Generation

1. **Random Instance Creation**:
   - Generate depot at random coordinates
   - Place customers randomly in [0,1] × [0,1] space
   - Assign random demands from specified range
   - Set vehicle capacity to ensure feasible solutions

2. **Traditional Solver Application**:
   - Use Nearest Neighbor heuristic for initial routes
   - Apply 2-opt local search for improvement
   - Generate ground truth routes and distances

3. **Dataset Creation**:
   - Default: 500 training + 50 validation instances
   - Each instance: 20 customers (configurable)
   - Capacity range: [80, 120] units
   - Demand range: [5, 20] units per customer

### Phase 2: Supervised Learning

1. **Target Sequence Creation**:
   - Convert optimal routes to decision sequences
   - Add depot returns and route separators
   - Handle capacity constraints and route boundaries

2. **Training Loop**:

   ```plaintext
   For each epoch:
     For each batch:
       1. Convert instances to model format
       2. Simulate decision-making process
       3. Compute cross-entropy loss vs ground truth
       4. Backpropagate and update weights
       5. Save epoch checkpoint
     Validate on held-out instances
     Update learning rate
   ```

3. **Loss Function**:
   - Cross-entropy loss between predicted and ground truth next customer
   - Applied at each decision step during route construction
   - Accumulated across all decision points in the sequence

### Phase 3: Model Optimization

- **Optimizer**: Adam with weight decay (1e-6)
- **Learning Rate**: 1e-4 with step decay
- **Scheduler**: Reduce LR by 0.5 every 30 epochs
- **Batch Size**: 16 instances per batch
- **Training Duration**: 30 epochs (configurable)

### Checkpoint System

The training process saves comprehensive checkpoints:

- **Location**: `trained_model/checkpoint-{epoch}.pt`
- **Contents**: Model weights, optimizer state, training loss, epoch number
- **Final Model**: `trained_model/trained_cvrp_model.pt`

## Data Generation

### Traditional CVRP Solver

Our training data comes from a hybrid traditional algorithm:

#### 1. Nearest Neighbor Construction

```python
def nearest_neighbor_route(start_node, unvisited, coordinates, demands, capacity):
    route = [start_node]
    current_load = demands[start_node-1]
    current_node = start_node
    
    while unvisited and current_load < capacity:
        # Find nearest feasible customer
        nearest = find_nearest_feasible(current_node, unvisited, demands, 
                                      capacity - current_load, coordinates)
        if nearest is None:
            break
        route.append(nearest)
        current_load += demands[nearest-1]
        current_node = nearest
        unvisited.remove(nearest)
    
    return route
```

#### 2. 2-Opt Improvement

```python
def two_opt_improvement(route, coordinates):
    improved = True
    while improved:
        improved = False
        for i in range(1, len(route)-2):
            for j in range(i+1, len(route)):
                if j - i == 1: continue
                
                # Calculate improvement from edge swap
                old_distance = distance(route[i], route[i+1]) + distance(route[j], route[j+1])
                new_distance = distance(route[i], route[j]) + distance(route[i+1], route[j+1])
                
                if new_distance < old_distance:
                    # Reverse segment between i+1 and j
                    route[i+1:j+1] = route[i+1:j+1][::-1]
                    improved = True
    return route
```

#### 3. Multi-Route Construction

The solver constructs multiple vehicle routes:

1. Start with all customers unvisited
2. For each route, apply nearest neighbor from depot
3. When capacity is reached, return to depot
4. Start new route with remaining customers
5. Apply 2-opt improvement to each route
6. Calculate total distance across all routes

### Data Quality Assurance

- **Feasibility Check**: All routes respect capacity constraints
- **Duplicate Prevention**: Fixed bug preventing customers from appearing in multiple routes
- **Distance Calculation**: Euclidean distance with proper depot returns
- **Statistics Logging**: Track dataset quality metrics

## Troubleshooting

### Common Issues and Solutions

#### 1. CUDA Out of Memory

```plaintext
RuntimeError: CUDA out of memory
```

**Solutions**:

- Reduce batch size: `batch_size=8` instead of 16
- Reduce problem size: `n_customers=15` instead of 20
- Use CPU training: `use_cuda=False`

#### 2. Model Loading Errors

```plaintext
FileNotFoundError: Model not found
```

**Solutions**:

- Check file path: Use absolute paths or verify working directory
- Train model first: Run `python train_cvrp.py`
- Verify checkpoint: Use `load_checkpoint_example.py` to test

#### 3. Benchmark Parsing Issues

```plaintext
KeyError: Missing required field in .vrp file
```

**Solutions**:

- Verify file format: Ensure VRPLIB standard compliance
- Check file encoding: Use UTF-8 text encoding
- Validate solution files: Ensure .sol file matches .vrp instance

#### 4. Poor Performance Results

**Symptoms**: High optimality gaps, poor route quality
**Solutions**:

- Increase training data: `n_train=1000` or more
- Longer training: `epochs=50` or more
- Better initialization: Train on diverse instance sizes
- Hyperparameter tuning: Adjust learning rate and model parameters

#### 5. Training Convergence Issues

**Symptoms**: Loss not decreasing, unstable training
**Solutions**:

- Lower learning rate: `learning_rate=5e-5`
- Gradient clipping: Add gradient norm clipping
- Better data quality: Ensure ground truth solutions are optimal
- Regularization: Increase weight decay

### Performance Optimization Tips

1. **Use GPU**: 10-20x speedup over CPU training
2. **Batch Processing**: Larger batches improve GPU utilization
3. **Mixed Precision**: Use `torch.cuda.amp` for memory efficiency
4. **Data Loading**: Precompute and cache datasets
5. **Profiling**: Use PyTorch profiler to identify bottlenecks

### Debugging Features

- **Debug Mode**: Set `debug_mode=True` for detailed logging
- **Checkpoint Analysis**: Use `load_checkpoint_example.py`
- **Route Visualization**: Enable plotting in data generator
- **Loss Tracking**: Monitor training progress with saved plots
